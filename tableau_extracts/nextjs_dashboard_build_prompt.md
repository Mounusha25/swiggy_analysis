# Build prompt: Swiggy Market Intelligence — Next.js dashboard

Paste this whole document into Claude Code, Cursor, or whatever coding tool you're using to scaffold the project. It is self-contained.

## Project goal

Build a dark-themed, single-page Next.js dashboard called **Swiggy Market Intelligence** that presents the analytics already computed by an existing Python project. This is a presentation layer only — it must not recompute business logic (RFM scoring, health scores, city opportunity index, category quadrants) in JavaScript. All numbers must trace back to the CSV extracts described below, the same way the project's existing Tableau workbook does.

## Tech stack

- Next.js 14+, App Router, TypeScript
- Tailwind CSS for all styling — no CSS-in-JS, no separate stylesheet files
- Recharts for line/bar/scatter/donut charts
- `react-simple-maps` + `d3-geo` for the India state map — **use a real TopoJSON file**, never a hand-drawn or invented outline. Use `https://cdn.jsdelivr.net/npm/datamaps@0.5.10/src/js/data/ind.topo.json` (verified real India state boundaries; the `properties.name` field on each feature is the state name, e.g. `"Karnataka"`, `"Maharashtra"`, `"Uttar Pradesh"` — these match the `State` column in the data exactly, so join on that field directly, no lookup table needed)
- `papaparse` for reading the CSV extracts at build time in a server component (or an API route if you prefer live reads)
- No customer-facing runtime database needed — this is a static/ISR analytics dashboard, not a live transactional app

## Data source — single source of truth

Do not invent numbers and do not recompute scoring logic in JavaScript. All data comes from six CSVs already generated by the Python project's `export_tableau_extracts.py` (which itself calls the tested functions in `analytics_models.py`):

- `orders_enriched.csv` — 197,430 raw order rows plus derived columns: `State, City, Order Date, Restaurant Name, Location, Category, Dish Name, Price (INR), Rating, Rating Count, Year-Month, Quarter, DayName, DayOfWeek, Value_Segment, Food Category`
- `city_expansion_index.csv` — one row per city: `City, Orders, Revenue, Weighted_Rating, Restaurants, Categories, Growth_Rate, Order_Density, Cat_Diversity, Opportunity_Score, City_Tier` (Tier is one of Stars / Untapped / Emerging / Low Priority, already computed)
- `restaurant_health_score.csv` — one row per restaurant: `Restaurant Name, Revenue, Orders, Weighted_Rating, Last_Order, City, State, Revenue_Share, Recency_Days, Health_Score, Health_Tier` (Tier is Champion / Healthy / At Risk / Critical, already computed)
- `rfm_summary.csv` — 6 rows, one per RFM segment: `RFM_Segment, Entities, Avg_Recency_Days, Avg_Frequency, Total_Revenue, Avg_RFM_Score`
- `rfm_detail.csv` — one row per restaurant with full RFM scoring
- `cohort_retention.csv` — monthly restaurant-partner cohort retention matrix

Copy these six files into the Next.js project under `/data/`. Parse them once at build time (or via `getStaticProps`-equivalent server component data fetching) and pass typed data down to client components — don't re-parse CSVs on every render.

Do not recompute the Menu Intelligence Matrix quadrants (Stars / Cash Cows / Hidden Gems / Review Needed) from scratch — that requires a category-name-cleaning step (title-casing, singularizing plurals, excluding promotional junk categories like "combo", "dotd", "mcsaver") that already lives in the Python project's `dashboard_tabs.py`. ## Color tokens (dark theme)

Define these as Tailwind theme extensions or CSS variables in `globals.css` — use them everywhere, never hardcode a different gray or orange elsewhere in the app:

| Token | Hex | Use |
|---|---|---|
| `--bg-page` | `#0F1015` | page background |
| `--bg-card` | `#15161D` | card / panel surfaces |
| `--bg-card-hover` | `#1B1C24` | hover state on interactive cards |
| `--border-subtle` | `#23242C` | card borders, dividers |
| `--accent` | `#FF6B35` | primary brand accent — active nav item, primary chart line, primary buttons (same orange used across this project's Streamlit app, Excel report, and Tableau workbook — keep it consistent) |
| `--text-primary` | `#F2F2F0` | headings, KPI numbers |
| `--text-secondary` | `#8A8B93` | labels, muted text, axis ticks |
| `--tier-champion` / `--tier-stars` | `#6FCF97` | green — Champion health tier, Stars city tier |
| `--tier-healthy` / `--tier-hidden-gems` / `--tier-untapped` | `#56CCF2` | blue — Healthy health tier, Hidden Gems menu quadrant, Untapped city tier |
| `--tier-at-risk` / `--tier-cash-cows` | `#F2C94C` | amber — At Risk health tier, Cash Cows menu quadrant |
| `--tier-critical` / `--tier-review-needed` | `#EB5757` | red — Critical health tier, Review Needed menu quadrant |
| `--tier-low-priority` / `--tier-emerging` | `#4F4F55` | neutral gray — Low Priority / Emerging city tiers |

Typography: system sans-serif stack, KPI numbers at 20–24px/500 weight, section labels at 11px uppercase with `letter-spacing: 0.04em` and `--text-secondary` color, body/axis text at 10–11px.

## Layout shell

Fixed left sidebar (150–180px wide, `--bg-card` background): logo mark at top, then the 7 nav items below, each a row with a Tabler icon + label; the active page gets an `--accent` background pill with dark text, inactive items use `--text-secondary`. Main content area scrolls independently, `--bg-page` background, 16–24px padding, cards laid out in a responsive CSS grid (`grid-template-columns: repeat(auto-fit, minmax(...))`).

## The 7 pages

### 1. Overview
- KPI row (5 cards): Total Revenue (₹5.30 Cr), Total Orders (197,430), Avg Order Value (₹269), Restaurant Partners (994, with "899 flagged at risk" as a red sub-line), **Cities Covered (28, with "10 tagged Stars" as an amber sub-line)** — this replaces the non-existent "Customers" metric, since the dataset has no customer identifier.
- Monthly revenue line chart, Jan–Aug 2025, with a 3-month moving average as a second dashed line, both from `orders_enriched.csv` grouped by `Year-Month`.
- Quarterly bar chart (Q1 ₹1.97 Cr, Q2 ₹1.99 Cr, Q3 ₹1.34 Cr — note Q3 is partial, July–August only, label it as such).
- Day-of-week bar chart, Monday through Sunday, from the same source.

### 2. Geographic
- India choropleth map (`react-simple-maps` + the real TopoJSON above), filled by state revenue from `orders_enriched.csv` grouped by `State`, using a sequential orange color scale (`d3.scaleQuantize` from `--bg-card` toward `--accent`).
- Top 8 states and top 8 cities by revenue as horizontal bar charts, side by side (Karnataka/Bengaluru leads both by a wide margin — flag this concentration in a caption).
- Optional: a Pareto chart (cumulative % of revenue by city, sorted descending, with an 80% reference line) if you want to carry over that analysis from the Python project.

### 3. Segments
- Order-value segment breakdown (`Value_Segment` column: Budget/Standard/Premium/Luxury) — donut or bar, revenue and order count per segment.
- Veg vs Non-Veg split (`Food Category` column) — donut.
- Restaurant frequency tiers (Low/Medium/High volume, already a documented 40/80 percentile split in the Python project) — bar chart of restaurant count and total orders per tier.

### 4. Trends
- Same monthly revenue chart as Overview but larger, plus a Month-over-Month growth rate bar chart (green above zero, red below), computed as `pct_change()` on the monthly revenue series.
- Quarterly performance trend restated as a line rather than bars, for a different visual angle than the Overview page.

### 5. Insights
- Menu Intelligence Matrix: a real scatter plot (Recharts `ScatterChart`), x-axis = revenue share, y-axis = weighted rating, points colored by quadrant using the tier color tokens above, with reference lines at the median of each axis. Use the static JSON block provided above.
- RFM segment summary (`rfm_summary.csv`): a bar chart of restaurant count per segment (Champions, Loyal Partners, Big Spenders, At Risk, Hibernating, Emerging), plus a small table showing total revenue per segment.
- Price-vs-rating correlation: a scatter or a single correlation coefficient stat tile, computed from `orders_enriched.csv`.

### 6. SQL pipeline
This page doesn't need a live database. Pre-run the 12 queries from the Python project's `sql_pipeline.py` once, save each result as a small JSON file (they're all small, aggregated tables), and build a page with: a dropdown/tab selector for the 12 query names, a syntax-highlighted `<pre>` block showing the actual SQL text (copy it verbatim from `sql_pipeline.py` — don't rewrite it), and a table below rendering that query's precomputed result. This mirrors the "SQL Pipeline" tab in the existing Streamlit app without needing a live SQLite instance in the browser.

### 7. Expansion strategy
- City Expansion Opportunity Index: scatter plot from `city_expansion_index.csv`, x = Revenue, y = Opportunity_Score, point size = Orders, color = City_Tier (Stars/Untapped/Emerging/Low Priority using the tier tokens), with median reference lines on both axes. A ranked list/table of the top 10 cities by Opportunity_Score alongside it.
- Restaurant Health Score: donut chart of `Health_Tier` counts (Champion 2, Healthy 3, At Risk 899, Critical 89) using the tier color tokens, plus a table of the top 5 restaurants by Health_Score and the bottom 5 (the ones actually flagged Critical), sourced from `restaurant_health_score.csv`. Call out in a caption that the At Risk count is large mostly because most restaurants are single-city, lower-volume listings relative to national chains like KFC and McDonald's, not because 899 restaurants are all in real distress — this exact caveat was flagged during the Python analysis and should carry over here.
